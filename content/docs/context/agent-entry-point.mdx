The agent entry point is the first place an AI agent looks when working in a repository.

`AGENTS.md` is the standard repository-level instruction file used by AI coding agents. Individual agents may also support their own instruction files, such as `CLAUDE.md`.

The entry point gives the agent an initial mental model of the repository and directs it towards the project's deeper context.

It should tell the agent:

- where project knowledge lives
- how the repository is organised
- which documents are authoritative
- where to find architecture, requirements, decisions, research and domain knowledge

It is not the project's entire context. It is the starting point from which the agent discovers that context.

```text
AI Agent
   ↓
AGENTS.md / CLAUDE.md
   ↓
Project Context
   ↓
Codebase
```

## Initialise

`vatras:init` creates the initial AI development surface for a repository:

<Files>
  <File name="AGENTS.md" />
  <File name="CLAUDE.md" />
  <File name="VOCABULARY.md" />
</Files>

`AGENTS.md` provides the shared repository-level entry point. `CLAUDE.md` is an
Adapter: it contains exactly `@AGENTS.md`, nothing else. Claude Code reads
`CLAUDE.md`, not `AGENTS.md`, and `@` is an import that loads the file — a
markdown link would load nothing.

`VOCABULARY.md` is created too, but bare — a `# Vocabulary` heading, no terms.
It is the one exception to "structure only": `AGENTS.md` states it is read
before every operation, and that rule needs a real file to point at. The
terms inside it are still content, and still arrive later, one at a time, as
they're needed.

`vatras:init` creates nothing else. The rest of the Context Architecture —
`docs/`, `IDEAS.md`, and everything in them — is not scaffolded in advance.
It comes into being later, one piece at a time, when the subsequent Vatras
workflow first has something that needs recording.

The agent entry point is the door into the project. [Context Architecture](/docs/context/context-architecture) is what lies beyond it.
