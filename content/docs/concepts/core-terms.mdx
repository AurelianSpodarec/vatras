## Two kinds of thing

Everything Vatras deals with is either knowledge that persists or work that
happens to it.

One term sits on the seam between them.

```text
Knowledge that persists          Work that happens to it
        │                                  │
    Context                            Operation
    Artefact                           Primitive
    Vocabulary                         Methodology
        │                                  │
        └───────────── Skill ──────────────┘
```

| Term | Meaning |
| ---- | ------- |
| **Context** | Everything an agent can draw on, and what gets loaded when |
| **Artefact** | Knowledge that persists and is acted on |
| **Vocabulary** | The shared language of a project |
| **Operation** | Something done to project knowledge |
| **Primitive** | An operation that recurs across unrelated work |
| **Methodology** | How operations arrange into a process |
| **Skill** | An artefact that encodes an operation |

Each term below says what kind of thing something is. How each one works
belongs to its own section.

---

## Knowledge that persists

### Context

Everything an agent can draw on to understand a project, and the discipline of
what gets loaded when.

Some context persists between sessions — that is what artefacts are. Some is
supplied for one piece of work and gone afterwards.

Not all of it is loaded the same way. Most is read once it becomes relevant to
the work in hand. See [Context](/docs/context) for how that is organised.

### Artefact

A piece of project knowledge that is loaded and acted on.

A decision about which database to use, explained once in a conversation, is
not an artefact. The next agent has no access to it. Written down where that
agent will find it, it is.

**How to recognise one.** Ask whether anything consumes it. An artefact is
read as input to work. A file nothing ever loads is a file, not an artefact.

**How many.** It depends on the kind. Some are singular by design — a project
has exactly one vocabulary, at its root, always. Others accumulate: decisions
and research notes only ever grow in number. Where a kind accumulates, each
file is an artefact in its own right; the directory holding them is not.

**Where it stops.** Source code is not an artefact. Code is what artefacts are
*about*. Without that boundary, "knowledge that persists" swallows the entire
repository and stops meaning anything.

### Vocabulary

The shared language of a project.

Vocabulary is the one artefact every project has, kept at the root and read
before every operation. That is what separates it from the rest: an agent
cannot judge which decisions or research matter until it knows what the words
mean.

See [Vocabulary](/docs/context/vocabulary) for what belongs in it and how it
is maintained.

## Work that happens to it

### Operation

Something done to project knowledge. An operation may create, inspect,
challenge, transform or verify artefacts.

Initialising a repository is an operation. So is interrogating a model, or
researching an open question.

**How to recognise one.** Name what goes in and what comes out. If you cannot,
it is not an operation — it is a description of an activity in general.

### Primitive

An operation the methodology keeps returning to.

Primitives are not a separate kind of thing from operations. A primitive *is*
an operation — one fundamental enough to recur across different pieces of
work, whatever is being built.

**How to recognise one.** Ask whether it appears again in unrelated work.
`vatras:init` runs once per repository and never again; it is an operation and
not a primitive. Challenging a model happens continually, on every project.

The exact set of Vatras primitives is still being discovered. Treat the
current list as provisional.

### Methodology

The way operations arrange into a process: their order, what feeds what, and
the principles governing the whole.

Methodology is not a step and not a skill. It is the shape the steps make.

## Skill

A skill is where the two halves meet.

A skill is an **artefact that encodes an operation**. It is a file, so it
persists and is loaded like any other artefact. What makes it distinct is its
content: instructions for performing a particular piece of work.

`skills/init/SKILL.md` is an artefact. Initialising a repository is the
operation it describes.

This is why the two are so easily confused, and why the distinction is worth
holding:

```text
Operation
    ↓
Skill
    ↓
AI agent
```

The operation is the activity. The skill is how an agent is taught to perform
it. Change the skill and the activity stays the same; change the operation and
the skill has to follow.

## Classifying something new

These definitions are themselves subject to refinement.

When Vatras introduces a new concept, it should be clear whether that concept
is:

- an artefact
- an operation
- a primitive
- a skill
- context
- documentation
- or part of the methodology

Documentation is on that list and is not an artefact. This page is
documentation: it explains the system to a person. Nothing loads it, and
nothing acts on it.

The terminology should evolve from actual use rather than being defined
completely in advance.
