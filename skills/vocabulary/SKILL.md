# Vocabulary

Maintain the project's canonical vocabulary.

## Purpose

Help establish and maintain a shared language between the developers and AI
agents working on a project.

## Before changing the vocabulary

1. Read the existing `VOCABULARY.md` if one exists.
2. Inspect relevant project context.
3. Inspect the relevant code and documentation.
4. Identify existing terminology before proposing new terms.
5. Look for synonyms, overloaded terms and ambiguous concepts.

## When proposing a term

Prefer existing project terminology when it is clear and useful.

When terminology is ambiguous:

1. Identify the competing terms.
2. Explain what each appears to mean.
3. Identify whether they represent the same or different concepts.
4. Propose a canonical term.
5. Ask the developer to resolve genuine ambiguity.

Do not silently establish important terminology when the project owner has not
made the distinction clear.

## Updating the vocabulary

Only add a term when it has become sufficiently established to act as shared
project language.

Keep `VOCABULARY.md` focused on terminology and concepts.

Do not turn it into:

- an architecture document
- a requirements document
- a specification
- a scratchpad
- general project documentation

## Output

Update `VOCABULARY.md` when terminology has been resolved.

Explain what changed and why.
